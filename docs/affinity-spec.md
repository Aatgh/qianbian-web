# 契合度规则说明（2026-11-24）

## 产品原则

千变的目标是接近《钢铁侠》里的贾维斯：懂用户、记得用户、能主动帮忙。

但 Agent **永远无法彻底读懂一个人的主观思想**，人的想法、情绪和选择会变化。因此：

> **契合度最高 80%，不存在 100%。**

80% 表示「高度默契」，保留 20% 的不可知空间。前端展示、文案、进度环都必须按 80 为上限。

## 当前线上算法

当前版本由后端 `AffinityService` 计算，前端只负责展示：

```text
auto = 100 × (
  0.25 × 记忆 M +
  0.20 × 互动 E +
  0.20 × 反馈 F +
  0.20 × 审批 A +
  0.15 × 相识时间 T
)

最终分数 = min(80, auto + (手动校准 - 50) × 0.4)
```

分项：

| 项 | 含义 | 满分条件 |
|---|---|---|
| M 记忆 | 事实、偏好、事件 | 8 条事实/事件 + 4 条偏好 |
| E 互动 | 活跃天数、对话轮次 | 5 个活跃日 + 30 轮 |
| F 反馈 | 「有用 / 没用」比例 | 至少产生反馈后按比例 |
| A 审批 | 工具/命令放行比例 | 至少产生审批后按比例 |
| T 时间 | 相识时间 | 14 天 |

规则：

- 新用户 **从 0 开始**，不再有 50 分垫底
- 没有反馈/审批时对应项为 0
- 最终分数强制不超过 **80**
- 分档：
  - 0–19：初识
  - 20–49：正在熟悉
  - 50–79：默契渐成
  - 80：高度拟人（上限）

## 下一版目标

现有算法只能衡量「聊得多不多」，衡量不了「懂不懂你」。下一版会加入用户资料：

```text
资料完整度 30%
长期记忆   25%
互动深度   20%
信任授权   15%
反馈校准   10%
```

资料包括基础信息、偏好、形象、健康、重要日期、审美等；敏感字段单独授权和脱敏。产品仍需遵守 80% 上限。

## 前端要求

1. 不得写死 `+4`、默认 30%、100% 满分等演示逻辑。
2. 契合度必须读取后端 `GET /api/affinity` 的 `score`。
3. 展示上限 80；进度环按 80 计算满格。
4. 分档文案使用上面的 0–19 / 20–49 / 50–79 / 80。
5. `GET /api/affinity` 返回：

```json
{
  "score": 12,
  "autoScore": 12,
  "calibration": 50,
  "band": "正在熟悉",
  "components": { "M": 20, "E": 32, "F": 0, "A": 0, "T": 0.7 },
  "hint": "..."
}
```

6. 不要在前端自行修改分数；调校准走 `PUT /api/affinity/calibration`。

## 隐私边界

契合度提升依赖资料，但以下数据不能随意使用：

- 身份证号：不存原文、不发给模型，只保存验证结果和派生年龄
- 精确地址：默认只到城市/区县，门牌号单独加密授权
- 健康信息：单独授权、加密，默认不进普通提示词
- 真实照片：私有存储，不自动发给外部模型
- 所有资料：用户可查看、修改、删除、撤回授权
